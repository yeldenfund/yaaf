## What this run carries

Five version steps and the EMA reset, with effects of opposite sign. The records
this run replaced were produced by `5.0.0-FORMAL`, while the scorer file had
already reached 5.1.0 without ever being run against the population. So the run
carries every change from v5.1.0 to v5.6.0:

| version | change | direction |
|---|---|---|
| v5.1.0 | components and the Volume Axiom gate removed (`SPEC_CHANGE_v5.1.0.md`) | raises the attainable ceiling |
| v5.2.0 | `cum_trades = n_trades`, ending the accumulation (D11) | lowers CF, so lowers scores |
| v5.3.0 | `psr` computed with T = n_trades (D5, D6) | raises `psr` for positive-Sharpe agents |
| v5.5.0 | drawdown penalty capped at 20 R | raises scores with long drawdown tails |
| v5.6.0 | equal weights over the live components | raises the mean level |
| (state) | `ema` reset to `EMA_INITIAL` | lowers published scores until it converges |

The net per agent is not deducible from the signs; the table in this document is
the measurement.

v5.1.0 appears in that list because the first draft of this section omitted it.
The draft counted the four changes declared after the scorer file had already
reached 5.1.0, and so missed that the records being replaced predated 5.1.0 as
well. The omission is recorded rather than quietly corrected: the list of what a
re-score carries is the precondition for reading its table, and a precondition
that was wrong once should be visible.

The band counts produced before this run are historical, not wrong:
they were the output of the specification in force at the time. Every
published count must name the version that produced it.

## Why the state was zeroed

The reset touched `ema`, `round_history`, `total_trades` and `updated_at`. It left
`address`, `last_s_raw`, `last_sistema` untouched.

EMA: `S_RAW` under 5.0.0 had an attainable ceiling of 88.0208 over 9
components with `W_SUM` 0.96; under 5.6.0 it is 100 over 8 components
with `W_SUM` 1.0. They are not the same quantity, and smoothing across
that boundary averages incommensurable numbers. Recomputing the history
under 5.6.0 is impossible: there is one snapshot of payloads, not a
series.

`round_history`: the same reason, and because 379 of 391 windows held a
single repeated value.

`total_trades`: because the stored value was wrong - 259 of 309
addresses held a `total_trades` above their own fill count, which is
impossible without accumulation (v5.2.0, D11).

The pre-reset state is in table `yaaf_state_pre_5_6_0_formal`, so a published `SISTEMA`
remains reproducible from the state that produced it.

## The population result: eligibility is zero by arithmetic

`eligible` fell from 4 to 0 in this run and the maximum `SISTEMA` from 520.53 to
360.89. Neither is a statement about the agents. After one observation from a
reset EMA,

    EMA(1) = 0.85 x EMA_INITIAL + 0.15 x S_RAW x 10 = 255 + 1.5 x S_RAW

whose ceiling at `S_RAW = 100` is 405, against a contract threshold of 500. No
agent could have cleared the threshold in this round whatever it did. The
observed maximum confirms the identity: `255 + 1.5 x 70.6 = 360.9`.

Measured in `docs/evidence/sim_steady_state.py` over the 607 served YAAF
records, holding CF and SF at the values in each record:

| | |
|---|---|
| eligible now | 0 |
| eligible once the EMA converges | **34 of 607** |
| projected population ceiling | **715.16** |
| collection events for the leaders | 4 to 8 |
| mean `SISTEMA`, now to converged | 115.35 to 141.96 |
| addresses whose EMA rises / falls | 212 / 395 |

Three things in that table were first stated wrongly by this project's own
analysis, and the corrections are the reason the measurement exists:

Counting `S_RAW >= 50` gives **86**, not 34. That form assumes `CF = SF = 1`;
the real condition is `S_RAW x 10 x CF x SF >= 500`. The assumption overcounted
by 52 agents, and 86 was briefly quoted as a projection before being checked.

The mean `SISTEMA` **rises** while the majority of EMAs **fall** - 395 fall
against 212 that rise. The sign of the mean of a product was inferred from the
sign of the mean of one factor, which does not follow: the agents whose EMA
rises carry higher `CF x SF`, so they move the mean more. Composition, not level.

`CF x SF` is not concentrated low. A single sampled agent showed 0.166 and an
argument was built on it; across the population 253 agents are above 0.4 and 73
above 0.8.

What the table settles, and what it does not: the threshold of 500 is reachable
under this specification, so no threshold decision is forced - that was the worse
branch and it did not occur. It is a projection under stated conditions, not a
forecast, because CF grows with trade count and SF depends on score dispersion,
so both move with new collection.

The figure is published by `/stats` as `eligible_at_ema_steady_state`, computed
independently of the simulation above. The two agree at 34, by different code
over the same payloads.
